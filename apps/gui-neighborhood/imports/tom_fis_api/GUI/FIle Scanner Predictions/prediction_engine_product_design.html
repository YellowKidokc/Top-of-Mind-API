The Prediction Engine

A file organizer that earns trust by showing you what you were going to do — before you do it.
Product Design Document — POF Hub / File Intelligence System — v1.0 — July 3, 2026

The Core Idea

Every file organizer ever built says: "Trust me. I'll put your files where they belong."

Nobody trusts that. Not because the AI is wrong — but because you can't see its reasoning. It's a black box that wants permission to touch your stuff.

The Prediction Engine says something different: "Here's what you were about to do. Here's what I would do. Here's why mine is better. You decide."

That's not an organizer. That's a partner who's one step ahead of you and can prove it.

The trust equation: Trust isn't granted by a permission dialog. Trust is earned by being right repeatedly, visibly, and without hiding your mistakes. If you predict what the user was going to do and you're right 70% of the time, they'll start listening to your suggestions. If you're right 90% of the time, they'll start letting you do it automatically.

The Minimum-Action Method

You asked: what is the method with the least amount of actions to classify, rename, and reorganize files? Here it is.

Phase 1: Observe (Zero user actions)

0 The user doesn't do anything. The system watches.

The file watcher runs in the background. Every time a file is created, modified, moved, or renamed, the system records:

• What happened: file created/moved/renamed/deleted

• Where: source and destination paths

• When: timestamp, time of day, day of week

• Context: what app was active, what folder was open

• Pattern: does this look like the last 10 things the user did?

After 50 observed actions, the system has enough data to start predicting. After 200, predictions are reliable. The user has done zero extra work to teach the system.

Phase 2: Predict (Zero user actions)

0 The system builds a prediction model from observed behavior.

The prediction model is simple and interpretable (not a black box neural net):

• Path frequency: where does this file type usually end up?

• Naming pattern: how does the user typically rename this file type?

• Co-occurrence: what files usually move together?

• Time pattern: is this a morning cleanup ritual or an end-of-day archive?

• Chi-signature match: where do files with similar semantic scores land?

The model is a weighted vote of these five signals. No training data from other users. No cloud. All local. All from YOUR behavior.

Phase 3: Show (One user action per file)

1 When the user acts on a file, show the split-screen prediction.

This is the key interaction. The user was going to do something anyway. The system adds exactly one cognitive step: glance at the prediction, decide if it's better.

Four possible outcomes per file:

• Match — system predicted correctly. User clicks "Use theirs." Zero extra work.

• Better — system suggestion is better. User clicks "Use mine." User learned something.

• Worse — system got it wrong. User clicks "Use theirs." System learned something.

• Permanent rule — user clicks "Always do this." Future files auto-organize. Maximum leverage.

Over time, the "Match" rate climbs. When it passes 90%, the user switches to auto-pilot: "just do what you would do." That transition is voluntary, gradual, and earned.

Phase 4: Automate (Zero user actions — earned)

0 High-confidence predictions execute automatically. The user sees a log.

Once the system has proven itself on a specific file type in a specific folder, it stops asking. Invoices go to Finance/Invoices. Screenshots get dated. Build artifacts get cleaned. The user sees a quiet notification: "Organized 7 files this morning."

But — and this is the trust mechanic — the user can always pull up the log and see exactly what happened, why, and undo any action with one click. Transparency doesn't go away when automation arrives.

Total action count to fully organize a file system:
Phase 1: 0 actions (observe 50-200 file events, happens naturally)
Phase 2: 0 actions (model builds automatically)
Phase 3: 1 action per file for ~100 files (the split-screen phase, with "Always do this" buttons reducing future work)
Phase 4: 0 actions per file (earned automation)

Compare to every other organizer: configure rules → drag files → create folders → rename manually → repeat forever.
This system's total cost is ~100 one-click decisions spread over the first month, then zero ongoing effort.

The Order of Operations

You asked: in what order should classify, rename, and reorganize happen? The order matters because each step feeds the next.

1
CLASSIFY first.

Before you can rename or move a file, you need to know WHAT it is. Classification is read-only — it doesn't touch the file. It just answers: what type? what domain? what project? what chi-signature? This takes 0.35 seconds per file with the semantic scorer, zero API calls.

2
RENAME second.

Now that you know what the file IS, you can name it properly. The rename suggestion uses the classification result + the user's naming patterns + the folder context. Rename is low-risk (reversible, logged, doesn't move anything) so it's a safe early action.

3
DEDUPLICATE third.

Before moving files, remove the copies. No point organizing 3 copies of the same PDF into 3 different "correct" folders. Hash comparison is fast and definitive — identical hashes = identical files, no ambiguity.

4
REORGANIZE fourth.

Now move files to their correct locations. This is the riskiest step (can break references, lose context) so it goes last, after you've classified, named, and deduped. The prediction engine shows where the file should go and why.

5
LEARN last.

Every accept/reject/override from steps 2-4 is a learning signal. The system updates its prediction model. Next time the same file type appears, the prediction is closer to what the user actually wants.

CLASSIFY → RENAME → DEDUPLICATE → REORGANIZE → LEARN
   |           |          |             |           |
   |           |          |             |           └─ update prediction model
   |           |          |             └─ move to correct folder (reversible)
   |           |          └─ hash compare, pick keeper, archive rest
   |           └─ suggest name, show split-screen, apply
   └─ semantic score, chi-hash, meta-classify (read-only)

Each step is independently valuable. If the user only does step 1, they have a classified file system. If they do 1-2, they have well-named files. If they do 1-3, they have no duplicates. The system degrades gracefully — partial adoption still helps.

What Makes This Different From Everything Else

1. The prediction is the product.

Most organizers organize. This one predicts. The organizing is a side effect of accurate prediction. If the prediction is wrong, you see it immediately and the system learns. If the prediction is right, the organizing happens automatically. The prediction engine is the thing you sell. The file organization is the thing it does.

2. Trust is earned visibly, not requested.

No "grant full disk access" dialog on day one. The system watches passively, then starts showing predictions without acting on them, then asks for per-file confirmation, then earns automatic trust for specific file types. The user can see their trust level increasing and can revoke it at any time for any category.

3. The user sees the reasoning, not just the result.

"I'm putting this in Finance/Invoices/2026 because: (a) you have 14 other invoices there, (b) the chi-signature is M=0.9, (c) you moved the last 3 invoices there, (d) the filename contains 'invoice' and '2026'." Four reasons. All verifiable. No "AI magic." The user can look at each reason and say "yeah, that's right" or "no, reason (c) is wrong because I changed my system last week." Then the system updates.

4. The "Always do this" button is the killer feature.

Every time the user confirms a prediction, they can make it a permanent rule. "Always put invoices in Finance/Invoices/{year}." One click. That rule now handles every future invoice automatically. The user builds their own automation, one rule at a time, without writing a single rule. The rules are just crystallized predictions that proved reliable.

5. Zero configuration. Zero onboarding.

The user installs it. It watches. It starts predicting. There is no setup wizard, no "select your folder structure," no "choose your naming convention." The system discovers all of that from behavior. The user's existing habits ARE the initial configuration.

The Trust Ladder

Trust isn't binary. It's a ladder with visible rungs.

0
SILENT OBSERVER — Days 1-7

The system watches but does nothing visible. It's learning your patterns. No UI, no popups, no suggestions. Just a small icon in the system tray that says "Learning... 34 of 50 actions observed."

1
PREDICTION ONLY — Days 7-14

The split-screen appears when you act on a file. It shows its prediction but doesn't do anything automatically. You can ignore it entirely. It's proving it can predict, not asking for permission to act.

2
SUGGESTION + CONFIRM — Days 14-30

For file types where prediction accuracy is above 80%, the system starts suggesting proactively: "You just downloaded an invoice. Move to Finance/Invoices/2026?" One click to accept. The user is still in control but the system initiates.

3
AUTO + LOG — Day 30+

For file types where prediction accuracy is above 95% AND the user has clicked "Always do this," the system acts automatically and logs it. A quiet daily summary: "Organized 12 files today. 3 invoices → Finance, 7 screenshots → renamed with dates, 2 duplicates → archived."

4
FULL PARTNER — Month 2+

The system knows your file system better than you do. It can answer questions: "Where did I put that invoice from March?" It can warn you: "You're about to create a file in a folder that has 500 items — want me to create a subfolder?" It's not an organizer anymore. It's an assistant that understands your information architecture.

The Prediction Model

How the system actually predicts what you're going to do. Five signals, weighted by reliability.

Signal 1: Destination Frequency (weight: 0.35)

Where have files like this ended up before? Group by extension + chi-signature. If the last 10 .pdf files with M-dominant chi-scores all went to Finance/, that's a strong signal.

Implementation: SELECT dest_path, COUNT(*) FROM file_actions WHERE ext = ? AND dominant_chi = ? GROUP BY dest_path ORDER BY count DESC

Signal 2: Naming Pattern (weight: 0.25)

How does the user name files of this type? Extract patterns: does the user prefix with dates? Use underscores or hyphens? Include project names? Capitalize?

Implementation: Store the last 50 renames. Extract regex patterns. When a new file of the same type appears, apply the most common pattern.

Signal 3: Temporal Context (weight: 0.15)

When is the user organizing? Monday morning cleanup = different behavior than Friday evening archive. Time-of-day and day-of-week correlate with different organizational modes.

Implementation: Bucket actions by hour and day-of-week. Weight recent patterns more than old ones (exponential decay, halflife = 30 days).

Signal 4: Folder Context (weight: 0.15)

What's already in the destination folder? If the user drops a file into a folder that already has 20 similar files, that's a strong signal. If the folder is empty, the signal is weak.

Implementation: Chi-signature centroid of the destination folder. Compare incoming file's chi-signature to the centroid. High similarity = high confidence.

Signal 5: Co-occurrence (weight: 0.10)

What files move together? If the user always moves .py files and .json files together when they're in the same folder, that's a project-bundling signal.

Implementation: Track which files move within 60 seconds of each other. Build association rules. When one file of a pair is moved, suggest moving the other.

Final prediction = Σ(signal × weight × recency_decay)

The prediction is a weighted vote, not a neural network. The user can understand it. "I'm suggesting Finance/ because: 35% of the signal says your .pdf invoices go there, 25% says your naming pattern matches, 15% says you do this Monday mornings, 15% says Finance/ already has 14 similar files, 10% says invoice files co-occur with receipt files that are already there."

Every part is inspectable. No black box.

The Market Reality

Who needs this: Everyone with a Downloads folder they're embarrassed about. Every knowledge worker drowning in documents. Every researcher with files scattered across drives. Every small business owner who can't find that contract from March.

Why nothing else works: Existing tools either (a) require the user to set up rules first (nobody does this) or (b) make decisions without explaining them (nobody trusts this). The prediction engine requires zero setup and explains everything.

What you actually sell: Not file organization. You sell the feeling of control over your digital life. "I know where everything is. I know why it's there. And it got there without me thinking about it."

The moat: The prediction model is trained on YOUR behavior, not anyone else's. It gets better the longer you use it. Switching costs are high because no competitor has your behavioral data. This is a product that gets stickier over time, not less.
